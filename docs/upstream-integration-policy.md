## 决策优先级与升级授权

- **用户明确提出或确认的个人修改、保留要求，是本项目产品决策的最高优先级。**
  老板主线、官方新版及 AI 建议均不能覆盖；要改变这些要求，必须说明具体影响并由用户明确确认。
  用户后续明确修订同一要求时，以最新答复为准，旧记录同步更新。
- 保护的是用户要求的行为，不是永久冻结某段实现。当前本地代码也包含上游能力和可能的缺陷，
  不能把“本地已有”一律当作用户亲自要求；来源或意图不明时先核查，无法确定再提问。
- **任何新版更新，先提交具体更新内容、行为差异、个人要求的保留方式和未解决冲突供用户确认；
  用户确认并说明如何处理后，才按其指定范围实施。**“无冲突采用最新版”是选用原则，
  不是自动更新、合并、迁移或部署授权。确认内容但未说明实施安排时，继续等待安排。
- 可以将无冲突更新汇总确认，不逐个重问已有选择。用户已在同一指令中确认内容并明确实施范围时，
  不要求重复确认；只处理新发现的冲突或超出该范围的事项。

## 密钥智能路由

2026-10-09，用户指定参考 `kiss-kedaya/sub2api`，在源码研究和多轮对齐后明确要求按以下范围
实施。原范围及 2026-10-10 追加的内外层调度、账号近期表现已完成实现；用户随后明确
授权合并、提交、推送和部署，现已上线。来源与验证见
[智能路由记录](upstream-sync-state.md#密钥智能路由与重连避让)。

- 创建/编辑密钥可按优先级添加、删除、排序候选组，最多 10 个。四类厂商卡片只筛选可选项，
  智能路由已选列表允许跨厂商保留；兼容性由请求协议、模型/映射及实际账号能力决定，
  不因故障切换擅自替换模型。旧单组密钥保持原行为，快捷切组不能意外清空备用项。
- 覆盖 Messages、Responses、Chat Completions 普通与流式文本，保留既有协议转换，不增加
  参考版的新转换开关。WebSocket 仅在可安全重新发起首轮时换组；已建立的上游会话不搬家，
  依赖 `previous_response_id` 的续接保持归属绑定。Gemini 原生、图片、视频暂不增加跨组路由。
- 模型不兼容或无可用账号时跳过。用户于 2026-10-10 明确同一套餐混有自营和多个供应商，
  并进一步明确按“一个账号就是一条供应商线路”处理：发生需切换的可重试故障时，先尝试
  同套餐其他可用账号，没有可用账号再尝试客户配置的备用套餐。
  故障排除以账号身份为单位，不增加供应商/线路标记，不按域名合并账号或推断跨账号同源；
  同一请求换套餐后仍避开已经失败的同一账号。此要求替代此前“报错立即让出整组”的选择，
  当前代码已按该顺序适配并部署。
  候选套餐按顺序推进，同套餐内可尝试多个不同账号，遵守整体尝试上限、取消和安全重放限制。
- 已向客户端输出实际内容后不重放，但可归因于上游的故障仍用于后续请求避让。
  主组停用、授权撤销或订阅失效不能提前挡住合格备用；每个候选独立校验权限、收费资格、
  模型能力和原有调度条件。人工暂停、质量、救治、严格冷却、用户及密钥配额继续有效。
- 分组失败偏好按“密钥 + 请求端点 + 请求模型 + 分组”隔离，在 Redis 保存 60 秒，
  后续请求和应用实例优先尝试未失败候选；合格候选耗尽后可在预算内尝试软避让项。
  当前实现到期恢复配置顺序，再失败则续记；不全局停用整个组，不牵连其他密钥或模型。
  2026-10-10 用户追加要求：成功切到备用套餐后，同一对话优先保留健康的备用套餐，
  新对话按配置顺序选择；继续按该备用套餐收费。会话套餐亲和使用显式会话标识单独保存，
  不以 60 秒失败偏好冒充此能力，已有响应 ID/上游会话绑定仍须遵守。
  Redis 偏好不可用时回到配置顺序，不放宽权限或调度保护。
- 健康判断复用真实调用与现有账号调度、冷却状态；渠道汇总绿灯不作为即时可用保证。
  不新增每请求同步探测、定时收费探测或全局分组熔断。客户端取消、参数错误、本地策略或
  额度拒绝不记为上游故障。用户明确先沿用现有超时配置，重点解决报错后反复走坏线路。
- 按实际命中组的倍率和收费方式计费，允许订阅与余额组混用；备用可能更贵。
  倍率和扣费归属以本次实际使用的客户套餐为准：余额套餐扣余额，订阅套餐扣订阅额度。
  管理员内部借用账号池不自动等于客户切换套餐；需区分客户计费套餐和实际账号来源。
  用量、订阅额度和审计按实际客户套餐记录，全局用户 RPM 每个客户端请求只准入一次，
  各候选仍检查自身组 RPM。主组与有序列表原子保存，鉴权缓存、模型列表与分组维护配套更新。

## 救治

- 救治默认关闭，无默认救治组；连续通过阈值默认 3，清扫间隔默认 5 分钟，显式配置优先。
- 入区保持停调并保存原组。救治期间不能改变或清空分组，组集合不变时可编辑其他设置；
  毕业或手动终止后可编辑分组。
- 手动终止恢复严格校验的原组、保持停调、不计恢复，阻止宿主和插件自动再次救治。
  [质量范围外明确手动开启](local-customizations.md#质量调度限制分组)可以同事务终止并开调度。
- 手动重新入区清除终止阻断，保存当前分组为新轮原组，保持停调，不清除独立人工暂停。
- 缺失、null、损坏或非法原组快照拒绝退出/毕业；明确空数组合法。目标组删除时整体回滚。
- 检测记账保留原始标记、原组快照和未知字段，不能把损坏快照容错改成空数组。
- 普通设置保存保留数据库当前调度状态。旧清扫、回调和探针不能更改新轮次或重启终止账号。
- 毕业要求当前轮次、15 分钟窗口内的插件与宿主资格联合证据；不能仅凭 on_duty/normal
  或插件离线缓存恢复。毕业事务一起恢复分组和调度。
- 关闭救治后允许终止和满足证据条件的收尾，不启动入区、种子、重新绑定或自动资格检测。
  可以读取当前桥状态；桥不可用时保持隔离。

`backend/internal/service/openai_rescue_recovery.go` 及仓库层的救治事务。

## 账号并发数与优先级

- 新建、单账号编辑、批量编辑和列表快捷编辑允许修改并发数和优先级。

- 并发为正整数；优先级为非负整数，越小越优先，允许 0。新建兼容旧 API：
  并发缺省或 0 使用默认 5，优先级缺省使用 2、明确 0 保留；更新时明确并发 0 拒绝。
