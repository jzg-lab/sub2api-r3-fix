## 授权、代理和导入

- 无代理的 OpenAI OAuth 首次授权、重新授权、检测和调用均保留直连。
- 有代理路径沿用本项目现有规则，不新增固定出口白名单、原登录 IP、浏览器证明等必需条件。r17bg 的这些限制不纳入当前产品规则。
- 显式指定的代理无效、失效或配置变化时拒绝，不静默回退直连。影子账号保留父账号代理继承。
- 保留现有账号身份/代理绑定、会话校验、一次性兑换和并发保护。
- 后台刷新凭据必须比较开始刷新时的凭据/代理快照。保存失败不修改调用方快照、不发布新令牌缓存、不重复使用已经消耗的 refresh token。这种并发保护不属于新增授权门槛。
- 普通导入立即启用；救援及明确资格流程继续使用各自闸门。

## 救援与并发

- 救援期间不能改变或清空分组；分组集合不变时可编辑其他设置。毕业或手动终止后可编辑分组。
- 手动终止恢复严格校验的原组，保持停调，不计恢复成功，阻止宿主和插件自动再次救援。
- 手动重新入区清除终止阻断，保存当前分组作为新轮原组，保持停调，不清除独立人工暂停。
- 缺失、null、损坏或非法原组快照拒绝退出/毕业；明确的空数组合法。目标组删除时整体回滚。
- 检测记账保留原始标记、原组快照及未知字段，不能容错修成空数组。
- 普通设置保存保留数据库当前调度状态。旧清扫、回调和探针结果不能更改新轮次或重新启用已终止账号。
- 关闭救援后允许终止和符合证据条件的收尾，不启动入区、种子、重新绑定或自动资格检测。
- r17bg 起，符合毕业条件指当前轮次的插件与宿主资格联合证据，不以单独的 on_duty/normal 状态或插件离线缓存作为恢复证明。关闭救援后的收尾可以读取当前桥状态；桥不可用时保持隔离，不能绕过证据毕业。

完整历史及验收见 `r17bf-repair-results.md`、`r17bf-final-review-fix-plan.md`。

## 账号并发数与优先级

用户确认日期：2026-10-06。实施与回归记录见
[account-scheduling-settings-20261006.md](account-scheduling-settings-20261006.md)。

- 账号并发数和优先级可在新建、单账号编辑、批量编辑中修改；列表两列提供快捷编辑。
- 最新确认默认值：并发 5、优先级 2；明确填写的合法值必须贯穿前端、service、repository
  落库。此规则取代此前所有平台强制并发 50 的本地规则和对应旧测试。
- 并发数为正整数；优先级为非负整数，数值越小越优先，允许设置 0。
  新建兼容旧 API：并发缺省或 0 使用默认 5；优先级缺省使用 2，明确 0 必须保留。
  更新时明确的并发 0 拒绝，不当成缺省。
- OpenAI 新账号模板的并发仅用于未明确填值的请求，不能覆盖用户明确选择的值；
  不修改已保存的模板、代理、指纹等其他设置。模板也不应用到已有账号。
- 更新未提供的字段保持原值；复制保留源账号值。创建影子未指定并发时继承母账号，
  显式并发优先；影子创建的优先级 0 仍表示继承，创建后可通过编辑设置为 0。
- 仅修改并发/优先级不能改变代理、分组、人工暂停、救援状态或启停调度；不绕过保护。
- 不做将全池重置成 5/2 的数据迁移。已有历史 0 并发不在本轮自动清理或重新解释。
- 合并上游时检查常量所有写入调用点，必须运行记录中的前端、服务层和仓库层回归；
  不能只解除输入框只读，也不能恢复 repository 的固定常量写入。
