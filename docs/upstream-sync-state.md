### Linux TOTP 最小实现方案

以下为已采用的实现约束。实际路由、字段、错误和 Linux 依赖见
[授权辅助程序说明](../deploy/auth-browser/README.md)，源码及模拟集成均已验证。

1. **执行端**：沿用老板表单和现有授权会话/凭据应用流程，适配 Linux 执行器。
   先确认 oh-my-sub2api 所调用的真实 worker、依赖及可分发条件，再选择最小接入方式。
   优先复用已存在的可运行路径；不同时新建协议、浏览器、远程桌面三套登录系统。
   若需要额外常驻服务或必须调用管理后台的新接口，先给出具体依赖和部署影响再讨论。
2. **账号数据**：TOTP 归属上游账号，与本系统管理员登录的二步验证数据分开。
   优先在现有账号存储中保存加密密钥；不因增加一个字段就新建数据表。
   已有 `SecretEncryptor` 和 `backend/internal/repository/aes_encryptor.go` 可作为复用入口；
   必须核对固定密钥配置，不允许使用重启即变化的临时密钥保存长期数据。
   缺少稳定密钥时明确拒绝持久化，不能降级为明文；正式部署时核对密钥备份及恢复。
3. **导入契约**：优先扩展已鉴权的管理员账号写入接口，以明确的 Sub2API 账号 ID 关联，
   接收 `totp_secret`，兼容参考系统的 `mfa_secret` 命名；两者同时提供且内容不同则拒绝。
   密钥规范化并校验后保存；字段省略保持，非空合法值替换，显式清除采用独立明确语义，
   空字符串或无效值不得意外删除旧密钥。不能只提供数据库字段却没有后台可调用的写入路径。
   本轮以已有账号补充密钥为最小交付；不会以导入 TOTP 为由创建重复账号或清空 OAuth。
4. **读取与授权**：普通列表/详情不携带密钥；是否配置通过专用 GET 状态接口读取；通用导出和日志排除该密钥。
   页面可明确选择使用已存密钥或本次输入；已存密钥由服务端解密使用，不回填浏览器。
   本次输入不默认保存；保存/清除密钥和发起登录是独立操作，导入不自动触发登录或改变调度状态。
   自动授权仍需密码，本轮密码当次传入；只保存 TOTP 不等于具备无人值守重登能力。
5. **并发与结果**：绑定账号、代理、授权会话和凭据版本；登录完成核对真实身份后再原子应用令牌。
   刷新、重新授权、普通编辑均不得丢失密钥，也不得用旧快照恢复刚清除或替换的密钥。
   秘密不进入命令行参数或普通日志；执行器超时/取消后清理临时材料；人工挑战明确结束并提示原因。
6. **交付证据**：提供实际 API 路由、请求/错误样例、字段语义及 Linux 依赖说明，便于用户后台对接。
   用合成密钥验证导入、重启读取、并发更新、替换/清除、无权限拒绝和脱敏；
   真实 Linux 登录另行记录结果，模拟测试通过不能写成真实授权已通过。

已核查：参考仓库未包含外部协议 worker，故采用现有 Node/Chrome 的 Linux 无头路径。
