## 3. 固定边界

沿用 `upstream-integration-policy.md`：无代理直连、现有代理授权规则、普通导入立即启用、人工暂停、手动终止、原组快照保护、旧轮次隔离和原子毕业均保留。

资格检测与实际业务使用相同传输路径；检测通过仅形成当前轮次的资格证据，恢复分组和启用调度仍由已有毕业事务一起提交。旧任务、插件离线或缺失状态不能打开恢复闸门。

本轮不新增插件链、双插件同时运行框架或通用质量状态机。先使用现有安装器、配置、桥状态、账号轮次和隔离测试工具；必需的新字段保持最小范围。

## 4. 第一阶段：补齐升级与替换条件

### 4.1 迁移历史兼容（最先实施）

位置：`backend/internal/repository/migrations_runner.go` 及现有迁移测试。

1. 对照目标数据库完整迁移清单和候选源码，不只处理第一次报错。确认缺失、改名、校验和变化和后续破坏性迁移。
2. 为已核实的 `238` 至 `246` 建立明确的新旧文件名映射，并绑定经核实的内容校验和。不按数字前缀或任意同 checksum 自动推断等价关系。
3. 对这组映射读取存在的完整名记录及别名记录。记录校验通过才视为已执行；双记录冲突、未知 checksum 或查询失败均报错。完整名已有错误记录时，不能用一个正确别名掩盖错误。
4. 只有别名记录且内容匹配时跳过重复 SQL，记录非敏感诊断；保留历史记录，不自动插入或改写迁移账本。两个名称均无记录时正常执行。
5. 保留已有迁移锁、事务和原有特定 checksum 兼容逻辑；新增别名规则不扩大旧白名单。既有 SQL 文件保持不可变。
6. 保留两个内容不同的 `247` 迁移。`248` 会删除旧票据表及字段，必须在备份副本上验证，不能把回退镜像当作恢复已删除数据的方案。

验收：空库、上游完整名历史库、r3 别名历史库、混合历史库均能升级和重复启动；错误 checksum、双记录冲突和查询失败明确拒绝。真实 PostgreSQL 验证触发器不重复创建；审计相关表/触发器，防止把已有历史账本当作实际结构完整的保证。

交付：针对性测试、从生产备份恢复到隔离库的升级报告、后续迁移影响和旧应用兼容性结论。未经副本验证，不再次启动候选宿主连接生产库。

### 4.2 新旧插件功能核对

核对安装记录、启用状态、非敏感配置、出站能力和实际调用路径。输出 BPS 与 Cookie Pin 的功能表：请求改写、模型处理、认证/代理、HTTP/流式/WebSocket、超时、失败处理和 Cookie/探针。

不同插件 ID 不属于原地版本升级；不得假设配置或功能会自动继承。先在隔离环境验证旧插件停用、新插件启用及回滚，保留旧包和配置。

如果 BPS 提供当前必须保留的能力，先评估最小迁移是否可行；无法兼容的行为交由用户决定，不能为了启用新插件默认放弃它。若不能替换，第一版保留生产旧插件，新插件继续在独立环境评估。

现有灰度按账号稳定散列比例选择，并非专用账号白名单。验证前读取实际启用比例；不把默认 100% 启用或低百分比启用当成专用测试隔离。

验收：必需能力逐项通过，替换失败能恢复旧插件；命中与未命中账号的路径可追踪，插件故障不会无声切换传输；客户流量不进入未经验证的实验。

### 4.3 自有签名与发布联合验收

复用已生成的本地发布密钥，不为每次构建生成新密钥。只在宿主配置中追加对应公钥，保留原公钥，保持 `allow_unsigned: false`。明确这是本项目自行维护的发行包，不能宣称作者签名。

仅修宿主迁移不要求重发内容相同的插件。若修改探针行为或配置协议，插件升为 0.3.10，同步清单、运行时、构建路径、测试及文档，保留 0.3.9 包原件。宿主记录合法版本和实际提交哈希，镜像使用固定提交标签。

使用最终签名包、计划采用的信任配置和准确宿主版本，在隔离环境运行真实安装器与 RPC 联合验收，包含暂停、重入、迟到回包、凭据/代理变更和包恢复。缺少实际包或配置的跳过用例不能写作通过。

## 5. 第二阶段：改进观测与判定

### 5.1 分开事实、启发式信号和操作

位置：插件 `internal/prober`、`internal/transport`，宿主资格判定及健康状态展示。

先记录 HTTP/传输结果、完整答案判分、usage 是否已知、reasoning tokens、截断信号、模型/effort、实际请求路径及重摇结果，再由规则决定操作。日志不含凭据、Cookie 值、业务原文或可识别的代理认证信息。

拟调整：正确回答但仅因 reasoning tokens 偏低时，记为中性可疑观察，不单独触发质量失败、Cookie 重摇或账号级定性；也不计入干净通过次数。缺失 usage、传输错误和截断观察沿用各自原因，不能伪装成通过。该规则在插件与宿主两端同步，否则插件停止重摇后宿主仍可能依据旧规则判失败。

检查现有“文本包含正确数字即通过”的判分，补充推导中出现正确数字但最终答案错误、否定正确答案和多个冲突答案的回归。优先采用明确最终答案的判分约定；无法可靠提取时记观察，不能靠字符串包含认定通过。

保留同源题库作传输和状态机一致性验证；效果评估增加不参与恢复计数的留出任务，避免训练判据和评估判据完全相同。不因缺少效果证据而直接降低毕业连过阈值或延长证据有效期。

验收：低 token 单一信号不再造成重摇链；错误答案不误通过；中性/错误观察不能毕业；当前轮次、人工暂停和事务约束全部通过回归。阈值调整必须有按模型、effort 分层的校准记录。

### 5.2 先测量成本，再补最小预算保护

统计每账号及整体的探针次数、重试、重摇、429、token 用量、恢复后复发和实际可用时长。未知 usage 单独计数，不能按零成本计算。

复用已有退避、重试上限、密集档预算和宿主节流。核对失败后预算重置、插件重启和多实例是否会反复绕开限制；若无法约束实验总流量，再补最小账号/整体预算，预算耗尽进入观察或退避，不打开调度、不解除暂停。

实验开始前在非敏感配置中记录明确的请求/token 上限和停止条件，不能用“持续救援”作为无限额请求许可。具体预算随专用账号额度和基线消耗确定，不凭空规定全生产默认值。

## 6. 第三阶段：真实效果对照

使用少量专用账号和隔离宿主，保证正常账号也参与，以估计误报。实验不同时运行旧插件和新插件去改变同一账号状态，不并发刷新同一组凭据。

固定模型、effort、代理出口、请求格式和评分规则；按账号进行随机交替的无 Cookie/保留 Cookie/清除后重建 Cookie 对照，限制并发。Cookie 存在延续效应，切换时明确重置并记录顺序和时间，不能把“清除后一定换节点”当作前提。

记录可见的 Cookie 获取/更新事件，不暴露值；在无法观测节点身份时，只能报告可观测效果，不能宣称证明了上游路由机制。人工重授权、更换代理、额度重置等变化单独记录，不能归因于 Cookie。

主要指标：留出任务正确率、正常账号误报率、恢复后复发率/可用时长、HTTP 错误和 429、探针成本。连续几次通过仅作系统的操作门槛，不称为完整质量保证或多个独立的质量证明。

预先记录预算、观察窗口和扩大范围的判据，不只挑成功案例。初步观察建议覆盖至少一天；样本小或正常账号基线不足时只报告探索结果，不承诺一天足以证明长期改善。对照无稳定收益时保留监测能力，重摇继续作为显式可选试验，不扩大自动救援范围。
