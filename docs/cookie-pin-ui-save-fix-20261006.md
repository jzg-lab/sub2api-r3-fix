## 根因

插件配置页的 `post()` 把参数包在 `params` 对象里，保存请求携带
`params.config`；宿主 UI Bridge v1 和 `PluginsView.handleBridgeMessage`
要求顶层 `config`。宿主在调用保存 API 前拒绝该消息。
同样的参数错位也影响 `ui.resize` 的顶层 `height`。

宿主错误响应的 `error` 是字符串，插件页面只读取 `error.message`，
因而实际拒绝理由被丢弃，仅显示通用“请求失败”。不据此归因于模型、账号或网络。

## 本地修改

- `deploy/codex-lb-cookie-pin/ui/index.html` 参数按 UI Bridge v1 放到顶层，
  不放宽宿主的来源、opaque origin、token、request ID 或二次验证检查。
- 同时支持字符串和对象形态错误，以及诊断失败结果中的 message。
- 保存从已加载配置合并当前表单值，保留未展示的高级探针参数。
  probe_model 明确传空字符串以清除固定模型；不重放历史一次性 Cookie drop。
- 配置未加载时拒绝保存，避免默认表单覆盖生产设置。
- 未改变探针默认关闭、主动流量、人工暂停、代理或资格检测边界。
