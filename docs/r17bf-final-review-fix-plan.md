# r17bf 最终复核问题修复计划

日期：2026-10-04；实施更新：2026-10-05

状态：四项修复、联合回归、构建和结果记录已完成。扩大范围测试中的已有失败已在基线复现并记录，不代表全后端测试通过。本计划补充 `r17bf-repair-plan.md`，以当前工作区为实施起点，包含已有未提交改动和未跟踪文件。

## 1. 目标和范围

修复最终独立复核已复现的四项问题：旧编辑重新开启救援调度、检测记账改写损坏快照、重入误清人工暂停、旧清扫退出新一轮救援。

按 Ponytail 原则，优先复用已有账号锁、事务、轮次标记、原子资格提交和插件暂停同步。预计无需新表、依赖或通用状态机；必要的查询条件和针对性回归属于本次修复范围。

用户已于 2026-10-05 授权实施全部四项修复、回归与结果记录。实施不撤销已有工作区改动，不自动修补历史数据；提交、发布和部署按后续明确指令执行。本地检查仅使用隔离数据库和模拟上游。

## 2. 要保证的行为

| 操作或状态 | 修复后的结果 |
| --- | --- |
| 保存名称等普通设置 | 保留数据库当前调度状态，不回写旧对象的调度值 |
| 账号进入救援 | 保存原组、保持停调；资格成功提交才可启用 |
| 检测通过后并发保存设置 | 保留已提交的启用结果，不被旧编辑再次停调 |
| 原组记录缺失或损坏 | 终止、毕业报错，原有分组和救援状态保持不变 |
| 明确记录原组为 `[]` | 合法恢复为空组 |
| 终止救援 | 恢复原组、停调、阻止宿主和插件自动救援；不改变原有人工暂停，不增加恢复次数 |
| 原本没有人工暂停，终止后重入 | 清除终止标记，继续新一轮救援，仍保持停调 |
| 原本已有人工暂停，终止后重入 | 清除终止标记，但保留人工暂停；自动资格针不能解除它 |
| 旧任务遇到账号已退出或重入 | 丢弃旧结果，不改变新轮次、不新增退出事件 |

人工暂停在此指现有宿主资格检测控制 `manual_paused`。插件终止暂停继续由终止名单控制，本次不扩大既有人工暂停对插件探测的含义。管理员明确发起的种子或诊断操作沿用既有语义。

## 3. 实施顺序

### 第一步：固化失败回归

将独立复核的临时用例纳入现有测试文件，先在当前工作区确认失败。复用已有服务桩和隔离 PostgreSQL 测试工具，不引入测试框架或重新搭建数据库。

四项数据库复现参考：

- `TestIndependentReviewStaleEditAfterEntry`：读取可调度账号，入区，再保存旧对象的名称；当前实现错误恢复调度。
- `TestIndependentReviewCorruptSnapshotPostgres`：移除原组快照，运行清扫记账，再终止；当前实现成功退出并清空分组。
- `TestIndependentReviewPauseBeforeTermination`：先人工暂停，再终止、重入；当前实现清除原有人工暂停。
- `TestIndependentReviewStaleSweepExitPostgres`：清扫持有旧退出快照，账号终止并重入，旧清扫继续执行；当前实现清除新轮次。

临时用例位于 `/tmp/r17bf-independent-review-service_test.go`、`/tmp/r17bf-independent-review-repository_test.go`，通过 `/tmp/r17bf-independent-review-overlay.json` 运行。它们作为复现参考，正式验收不依赖这些临时文件。

### 第二步：保护普通编辑的调度状态（P1）

主要位置：`backend/internal/repository/account_repo.go`，及其管理员/普通账号服务调用者。

- 先区分普通设置保存与明确启停操作，核对共享 `Update` 的实际调用者，避免改变内部专用写入。
- 在已有账号锁下取得当前调度状态。普通编辑保留当前值，不使用旧对象里的 `Schedulable`。
- 保留已有状态错误、过期和人工暂停等限制；专用资格提交和明确人工停调仍可改变调度。
- 对救援期间或终止后的批量启用等管理入口核查同一规则，不能绕过救援资格或终止限制。
- 若并发毕业刚完成，普通保存不得将已启用账号再次停调。失败仍整体回滚，沿用现有 outbox 和缓存同步。

验收：旧编辑不能把停调改为启用，也不能把刚通过资格的启用改为停调；单个、带分组保存和相关批量入口遵守同一规则。普通导入立即启用继续成立。

### 第三步：让原组快照保持原样（P1）

主要位置：`backend/internal/service/openai_rescue_lane.go`、`openai_rescue_termination.go`，及终止/毕业仓库事务。

- 种子和自动资格记账只修改检测字段：次数、时间、成功状态等。
- 从原始标记复制后修改相关字段，保留原组、入区轮次及未修改字段；不再从容错解析的结构体重建整份标记。
- 继续使用当前标记比较保护，防止并发修改被覆盖。
- 退出用的严格解析与界面容错展示区分：缺失、`null`、错误类型、混合非法内容、小数、非法或重复 ID 必须拒绝。
- 合法空组必须明确记录为 `[]`。目标组不存在或已删除时，沿用事务校验并整体回滚。

验收：种子成功、失败或自动资格记账后，损坏快照仍保持原样；终止和毕业均拒绝损坏快照，不猜测分组。合法空组和正常原组仍能恢复。

### 第四步：分开终止阻断与人工暂停（P2）

主要位置：`backend/internal/repository/openai_rescue_termination.go`、`openai_downgrade_probe_repo.go`、`openai_downgrade_commit.go`，以及服务预检和 `backend/cmd/server/wire_gen.go` 自动资格针装配。

- 使用已有 `openai_rescue_terminated_at` 作为终止阻断依据；终止不再覆盖 `manual_paused`，重入不再自动清除它。
- 到期任务查询、运行预检、资格排队和资格结果原子提交都检查终止标记。预检与数据库最终检查必须一致，迟到结果不能越过阻断。
- 自动资格针改为不允许解除人工暂停，并在排队事务中复核。保留管理员明确解除人工暂停的专用操作。
- 插件暂停名单继续由数据库终止标记派生；重入后同步解除该名单再发新种子。保留同步失败停止插件、其他实例周期补偿和配置保存/回滚保护。
- 更新健康列表和操作反馈，确保终止账号仍明确显示停止状态，人工暂停不会因终止阻断改用独立标记而误显示为可自动检测。
- 对已有“终止标记 + 人工暂停为真”的记录，无法可靠推断暂停来源时保留人工暂停，交由管理员明确解除。当前补丁尚未部署，实施时仍需核实目标环境，不能推测历史来源。

验收：原本未暂停的账号终止后不自动检测，重入后可继续自动资格；原本暂停的账号跨终止、重入始终保持暂停。自动资格针不能清除它。插件暂停及重入同步原有回归仍通过。

### 第五步：旧清扫携带旧轮次（P2）

主要位置：`backend/internal/service/openai_rescue_lane.go`。

- 清扫调用已有 `exitRescueEpisode` 时传入快照中的 `EnteredAt`，不再使用缺少轮次的退出调用。
- 继续由仓库在账号锁下比较期望标记；轮次已变化或账号已退出时按无操作处理，不重绑、不清标记、不新增退出事件。
- 核对其他异步出口是否丢失轮次，复用已有检查，不新增任务队列、轮次表或并行流程。

验收：持有历史 `auth_rejected` 快照的旧清扫，不能退出管理员刚开启的新轮次；当前同轮退出仍正常，重复退出幂等。服务测试和真实数据库测试都覆盖该顺序。

## 4. 联合验收

每项先通过自己的失败回归，再执行一次受影响范围的联合检查：

- 隔离 PostgreSQL：四项复现、并发编辑/入区/资格提交/终止/重入、事务失败回滚和 outbox 一致性。
- 后端 race：救援、探针控制和资格提交、管理编辑与重新授权、插件暂停相关测试。
- 保留定制：无代理直连，有代理失效拒绝，普通导入立即启用，人工暂停，影子账号代理继承。
- 插件：单元/race 和本地真实 RPC；名单同步、在途取消、重入、配置保存/回滚、失败停止进程继续通过。
- 前端：终止和重入入口、状态反馈；运行相关测试和类型检查，界面或文案有修改时补生产构建。
- 后端构建和差异检查；报告失败、跳过及验证范围，不能将专项通过写成全后端通过。

实际发布签名包、目标信任配置、生产历史数据和真实账号仍是发布前待办。已有两项图片失败须保留记录；本计划不以无关重构解决它们。
