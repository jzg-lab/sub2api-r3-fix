# Proposal: 判死号自动救治区（Rescue Lane）

## 背景

当前判死（pending_replace）是终态：主机探针永不自动复查（r17x 选项A），唯一出口是人工点
「重新启用」走一针结业冷针。两个已实证的缺陷：

1. **冷针是单次抽样**。路由级降智号（如实测 25% 坏签率的 2 号）有概率恰好抽中坏签被
   冤杀回 pending_replace，而停用状态下零流量 = 零探针 = 无人分型。
2. **插件只跟流量走**。lb-cookie-pin 插件的路由级救治（判别题探针 + 自动丢签重摇）只对
   有业务流量的在岗号生效；判死号零流量，永远进不了插件的守护循环。

sidecar 实验台（10/2）已验证救治机制有效：2 号 25% 错 → 丢签重摇 → 6/6 全对；同时
3/5 号跨两次重摇稳定答错 = 账号级，插件无解。救治区把这套手工流程工业化：判死号自动
进入带流量的救治环境，插件连续探针分型 + 换签治疗，机器判「已复活」，人工点击转正。

## 设计总览

```
判死(降智类) ──自动──> 救治区(绑救治组+开调度+标签「救治中」)
                        │  种子流量→插件15分钟体检→签坏自动换签
                        ├─ 6连干净 → 标签「已复活」(可点击)
                        │              └─ 人工点击 → 现有重新启用考证 → 上岗 → 插件守护循环
                        └─ 连错3次进退避 → 标签「疑似账号级」+ 自动撤调度
                                           (退避期满复探给新机会,状态回升「救治中」)
```

### 入口（三条，汇入同一转换函数）

| 触发 | 时机 | 说明 |
|---|---|---|
| ① 自动钩子 | 探针状态机落判死（降智类分类）瞬间 | 内嵌在既有 pending_replace 迁移点 |
| ② 对账清扫 | 编排器周期扫描（默认 5min） | 找「够格却未进区」的号自动补进，自愈自动钩子失效 |
| ③ 手动按钮 | 面板问题号行「送入实验台」 | 兜底 + 主动送查；与自动路径同一转换，落 audit |

入口过滤（三类不进区）：401/吊销死（插件治不了，走重新授权/退换）、429/额度死（不是
降智）、未分类判死。进区资格 = 降智类判死（答错/低rt/降智指纹/双信号熔断路径落判死）。
**落点已定案（Phase 0.3）**：三条判死路径全部经 processStateAtomic 单一提交点
（commit_svc.go:424-433 committed 块），钩子挂此处；过滤用 mutation.Events 的 reason
字段（credentials_invalid 排除）+ account.RateLimitResetAt（未来=429 排除）。

**✅ 原与自动打票线的冲突——已消除（2026-10-02 用户裁定「救号只保留救治区这条线，
其它救号的统统清理掉」）**：maybeAutoHarvestDead 及整条打票线（A 层 harvest 状态机 +
B 层 x-codex-turn-state 票表/采票观察哨/已停用的网关注入）已整体删除，migration 248
防御性清场。救治区成为判死号唯一自动救援线，让位闸需求不复存在。删除前生产实测
打票线零在途（0 行 probe_mode='harvest'，migration 纯防御）；guardOpenAICodexTurnStateEcho
跨账号剥头安全闸保留（业务流量在用）。

### 出口

| 出口 | 条件 | 动作 |
|---|---|---|
| 转正 | 标签「已复活」+ 人工点击 | 调既有 reenable 端点考证，通过后自动改绑回主池组 |
| 疑似账号级 | 插件连错 3 次进退避 | 自动撤调度（停烧额度）+ 标签；退避期满复探，回暖则恢复调度+「救治中」 |
| 人工了断 | 操作员对「疑似账号级」裁定 | 面板既有删除/静置操作，救治区自动清位 |

转正必须重新考证（冷针）：已复活号是健康的，冷针必过；考证通过后裁判（主机探针）
回归，防裸奔回主池。**不允许跳过考证直接回主池**——判死态在 ListDue 是排除项，跳过
考证 = 裁判永远失明。

### 标签（前端，账号健康格）

| 标签 | 颜色 | 数据源 | 交互 |
|---|---|---|---|
| 救治中 | 蓝紫 | 救治区成员 + 插件状态=active | 不可点；悬停显示救治时长/连过计数 |
| 已复活 | 绿 | 插件连过计数 ≥ 阈值(默认6) | **可点击** → 现有 reenable 确认弹窗 |
| 疑似账号级 | 灰红 | 插件状态=backoff | 不可点；悬停显示连错次数/退避到期时间 |
| (救治中·插件离线) | 蓝紫+警示角标 | 救治区成员但插件状态不可达>2min | 提示插件离线，调度行为不变 |

**救治区「已复活」标签 ≠ 复活号徽标，两个不同的东西：**

| | 救治区「已复活」 | 「复活」徽标 |
|---|---|---|
| 时机 | 救治区内，插件连过≥阈值 | **转正回主池后，永久** |
| 作用 | 转正触发器（可点击） | 血统标记：此号曾判死被救治，永不与「一直正常的号」混淆 |
| 数据 | 插件连过计数 | Extra 永久标记 rescued_at + 复活次数；悬停显示复活时间/次数 |

复活号徽标**不会因后续健康而消失**——它是 lineage，不是状态。复活号再次判死再次入区救治，复活次数+1。

### 流量种子（关键技术前提）

插件探针复用业务请求模板（指纹同形纪律），救治组无客户流量时插件无模板可探。宿主在
进区转换时自动打一发轻量种子请求。**载体已定案（Phase 0.1）**：service 层直调
`TestAccountConnection`（账号测试路径，不校验账号死活，目标 URL 与业务转发一致），该
路径过插件 Forward 钩子，且插件路由只看平台/OAuth/灰度桶、不看账号状态——零新增协议、
零指纹破坏。降智探针/转正冷针不过插件（保持无签冷启动语义，判定不被插件 Cookie 污染）。
种子只在进区时打一次，之后插件 15 分钟自循环。

### 换签时效计量与卡点（签寿命计量学）

用户要求（2026-10-02 追加）：换签后的可用窗口必须**精准实测**，复活号旁显示**读秒倒计时**，
探针循环按实测窗口**卡点**。三个部件：

**① 签寿命计量（插件）**：每次捕获记录 sign_captured_at；签死亡有三类实时信号——
a) 业务响应 faster-model 头（逐请求级，零延迟）；b) 质量探针答错（≤1 个探针间隔分辨率）；
c) TTL 刷新触发。死亡时刻 = 首个信号到达时。每账号维护滚动寿命统计（最近 N 次寿命的
p50/p80/最小值）。

**② 倒计时显示（前端）**：复活号徽标旁挂「签龄 mm/预计余 mm:ss」读秒芯片。数据源 =
状态桥的 sign_captured_at + 寿命估计（当前用 p80 减安全余量），前端本地逐秒走钟，
桥每次刷新（30s）校准。**诚实标注：这是估计值不是保证值**——__cflb/__oailb 是会话
Cookie 无 Expires 属性，硬 TTL 不存在，窗口是观测推断的；faster-model 实时信号到达
时倒计时立即归零触发重摇。数据积累越久估计越准。

**③ 循环卡点（插件探针排程自适应）**：下一针时间不再固定 15 分钟盲轮询，改为
`sign_captured_at + 实测寿命p80 - 安全余量` 附近（保留 jitter 抖动，防探针节奏与
换签时刻强相关形成可聚类指纹——自适应但不可预测）。年轻签期少探（省额度），临近
预期死亡密集探（早发现早换签）。退避/疑似账号级路径不适用卡点（无签可保）。

### 插件状态桥（Phase 0.2 后工程量大幅缩水）

插件 Health 响应**早已携带** status_json（官方协议字段 3，含每账号探针状态），fork
proto 缺该字段把数据丢了；插件 UI 也已每 5s 轮询 plugin.status 消息，只是 fork 桥没接。

1. fork proto 补字段（HealthResponse.status_json=3 / TestConfigResponse.status_json=4，
   与官方同字段号，wire 纯加法）→ 新只读端点 GET /admin/plugins/:id/status（内部调
   Health 透传）→ PluginsView 桥补 plugin.status case，插件面板「状态不可用」免费复活。
2. 插件 v0.3.0 只做 **status_json JSON 内容扩展**（不碰 proto/manifest——manifest 被
   双重 schema 锁死，加字段=拒装）：consecutive_passes 计数器（现在只有连错计数）+
   签寿命字段 `{sign_captured_at, sign_lifetime_stats{p50,p80,min,samples},
   estimated_remaining}`。官方 v0.2.11 零影响是结构性保障：宿主→插件方法只能宿主发起，
   官方产物没有新方法 stub，物理上发不出新调用。
3. fork 宿主桥接轮询（默认 30s）+ 进程内缓存 + 插件离线判定（>2min 无响应），暴露给
   标签计算与健康快照 API。

### 惩罚窗升级风险（已知情接受）

社区实证判死号持续使用会阶梯升级惩罚窗。救治区把「判死号带流量」制度化，风险敞口由
三重限制封顶：仅降智类进区、连错3次自动撤调度（敞口≤3探针周期）、转正必须人工点击。
用户已知情并裁定采用本设计（2026-10-02 会话裁定）。

## 变更范围

- **插件** `~/sub2api-cookie-plugin` 0.2.1 → 0.3.0：status_json 内容扩展（连过计数器+
  签寿命计量字段；不碰 proto/manifest）；签寿命计量（捕获/死亡时间戳+滚动统计）；
  自适应卡点探针排程（实测窗口+jitter）。
- **fork 后端**（r17ax）：插件状态桥；救治编排器（入口转换/对账清扫/种子/标签计算/撤
  调度恢复）；转正打复活标记（rescued_at/次数，永久）；手动入区端点；audit 事件；
  健康快照 API 扩展救治字段+签寿命字段；配置项
  `rescue_lane.*`（enabled/group/consecutive_clean_passes=6/reconcile_interval）。
- **fork 前端**：三标签 + 已复活点击接线 + 「送入实验台」按钮（可见性规则见上）+ 救治组
  管理提示 + **复活号永久徽标**（悬停复活时间/次数）+ **签余量读秒芯片**。

## 不做（Out of Scope）

- 救治组折扣客户档（商业模式，后续独立裁定）
- 自动转正（人工点击是明示设计，非省事）
- 自动退换/静置处置（疑似账号级的了断由人裁定）
- 修改插件探针节奏/指纹纪律

## 验收标准

1. sidecar 全流程 E2E：判死→自动入区→种子→插件探针→标签流转（救治中→已复活/疑似
   账号级）→已复活点击→考证通过→自动改绑回主池组。
2. 手动按钮三条可见性规则 + 幂等（已在区点击无副作用）+ audit 落账。
3. 自动钩子失效模拟（关掉钩子只留清扫）→ 5min 内对账补进。
4. 插件离线 > 2min → 标签降级显示，恢复后自愈；期间业务转发不受影响。
5. 铁律三段式构建校验过（候选 vs 在产 r17aw 特征串超集）；全量回归 + 新增测试绿。
6. 生产部署后：主池客户流量永远不落救治组（组隔离验证）。
7. 复活徽标永久性：转正后永不消失；再次判死复活次数+1；悬停信息正确。
8. 倒计时行为：读秒逐秒走钟、桥刷新校准、faster-model 信号到达立即归零换签；
   估计值标注清晰（不冒充保证值）。
9. 卡点排程：下一针落点 = 签捕获+寿命p80-余量 的窗口内且带 jitter（分布回归测试，
   验证与换签时刻无强相关）；省额度效果 = 年轻签期探针密度低于临近死亡期。
